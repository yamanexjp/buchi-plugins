# buchi:on — ぶちゲートウェイへ再接続する

以下の手順を**この順番で**実行する。手順を飛ばして書き込んではならない。

1. MCP ツール `buchi_on` を**引数なし（dry-run）**で呼び出す。
   この呼び出しは何も書き込まず、予定される差分（マスク済み）を返す。
2. 応答がエラーの場合は、応答文をそのままユーザーに提示して**中断**する。特に:
   - 初回セットアップ未実施（退避情報なし）のエラー →「初回は `/buchiai-gateway:setup`
     を実行してください」と案内して中断。
   - gateway_url / gateway_token 未設定のエラー →「`/plugin` から設定して
     ください」と案内して中断。
3. dry-run 応答（差分・注意事項。マスク済み）を**そのまま**ユーザーに提示し、
   「この内容で再接続してよいか」を確認する。
4. ユーザーの**明示的な同意**が得られた場合のみ、`buchi_on` を
   `{"apply": true}` で再実行する。同意が得られなければ何も書き込まずに終了する。
5. 適用後の応答（結果・healthz 疎通結果）を提示し、**「反映には Claude Code の
   再起動が必要です」**と必ず案内する。

## セキュリティ上の絶対条件

- トークンや userConfig の値を出力・引用・推測しない。表示は MCP ツールの
  応答（マスク済み）を**そのまま**使う。
- マスクされた値（`buchi_••••XXXX` など）から元の値を復元・補完しようとしない。
- settings.json を直接編集しない。変更は必ず MCP ツール経由で行う。
