# buchi:setup — ぶちゲートウェイに接続する

以下の手順を**この順番で**実行する。手順を飛ばして書き込んではならない。

1. MCP ツール `buchi_setup` を**引数なし（dry-run）**で呼び出す。
   この呼び出しは何も書き込まず、予定される差分（マスク済み）を返す。
2. 応答がエラーの場合は、応答文をそのままユーザーに提示して**中断**する。特に:
   - gateway_url / gateway_token 未設定のエラー →「`/plugin` から buchi プラグインの
     設定（gateway_url・gateway_token）を入力してください」と案内して中断。
   - saas モード未提供（O-1 確定待ち）のエラー → その旨を伝えて中断。
3. dry-run 応答（差分・注意事項。すべてマスク済み）を**そのまま**ユーザーに提示し、
   「この内容で settings.json に書き込んでよいか」を確認する。
4. ユーザーの**明示的な同意**が得られた場合のみ、`buchi_setup` を
   `{"apply": true}` で再実行する。同意が得られない・返答が曖昧な場合は、
   何も書き込まずに終了する。
5. 適用後の応答（結果・バックアップ先・healthz 疎通結果）を提示し、
   **「反映には Claude Code の再起動が必要です」**と必ず案内する。
   healthz が NG でも設定は保持されている旨（必要なら `/buchi:doctor` で診断、
   戻すなら `/buchi:off`）を伝える。

## セキュリティ上の絶対条件

- トークンや userConfig の値を出力・引用・推測しない。表示は MCP ツールの
  応答（マスク済み）を**そのまま**使う。
- マスクされた値（`buchi_••••XXXX` など）から元の値を復元・補完しようとしない。
- settings.json を直接編集しない。変更は必ず MCP ツール経由で行う。
