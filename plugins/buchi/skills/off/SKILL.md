# buchi:off — ぶちゲートウェイ接続を解除する

以下の手順を**この順番で**実行する。手順を飛ばして書き込んではならない。

1. MCP ツール `buchi_off` を**引数なし（dry-run）**で呼び出す。
   この呼び出しは何も書き込まず、復元予定の差分（マスク済み）を返す。
2. 応答がエラーの場合は、応答文をそのままユーザーに提示して**中断**する。特に:
   - 退避情報（state.json）が無いエラー → 応答に含まれるバックアップからの
     復元手順（`cp` コマンド）をそのまま提示し、実行するかはユーザーに委ねる。
   - settings.json が不正 JSON のエラー → 手動修復が必要である旨を伝えて中断。
3. dry-run 応答（現在値 → 復元先の差分。マスク済み）を**そのまま**ユーザーに
   提示し、「この内容で元に戻してよいか」を確認する。
4. ユーザーの**明示的な同意**が得られた場合のみ、`buchi_off` を
   `{"apply": true}` で再実行する。同意が得られなければ何も書き込まずに終了する。
5. 適用後の応答を提示し、**「反映には Claude Code の再起動が必要です」**と
   必ず案内する。再接続したくなったら `/buchi:on`（または `/buchi:setup`）で
   戻せることも伝える。

## セキュリティ上の絶対条件

- トークンや userConfig の値を出力・引用・推測しない。表示は MCP ツールの
  応答（マスク済み）を**そのまま**使う。
- マスクされた値（`buchi_••••XXXX` など）から元の値を復元・補完しようとしない。
- settings.json を直接編集しない。変更は必ず MCP ツール経由で行う。
